This section uses one SVD to get orthonormal bases for all four subspaces. Here is why that works, then how the code does it.

### The key identity

Start from $A = U\Sigma V^\top$ and multiply both sides by $V$ on the right. Because $V^\top V = I$:

$$AV = U\Sigma \quad\Longrightarrow\quad A\,v_i = \sigma_i\,u_i \quad\text{for each column } i$$

Doing the same with $A^\top = V\Sigma^\top U^\top$ gives $A^\top u_i = \sigma_i\, v_i$.

So A sends each right singular vector $v_i$ to the matching left singular vector $u_i$, stretched by $\sigma_i$. The singular values are sorted, $\sigma_1 \ge \dots \ge \sigma_r > 0 = \sigma_{r+1} = \dots$, so the vectors fall into two groups.

### Reading off the four subspaces

**In the input space ℝⁿ (columns of V):**
- For $i > r$: $A v_i = 0 \cdot u_i = 0$. So $v_{r+1},\dots,v_n$ lie in the **null space**.
- For $i \le r$: $v_i = A^\top u_i / \sigma_i$ is a combination of the columns of $A^\top$, which are the rows of A. So $v_1,\dots,v_r$ lie in the **row space**.

**In the output space ℝᵐ (columns of U):**
- For $i \le r$: $u_i = A v_i / \sigma_i$ is a combination of the columns of A. So $u_1,\dots,u_r$ lie in the **column space**.
- For $i > r$: $A^\top u_i = 0$. So $u_{r+1},\dots,u_m$ lie in the **left null space**.

These vectors don't just lie in the subspaces, they span them. For example, any $Ax$ can be written as $\sum_i \sigma_i (v_i^\top x)\, u_i$, and only the first r terms survive, so every vector in the column space is a combination of $u_1,\dots,u_r$.

### What you get for free

- **Orthonormal bases.** U and V are orthogonal matrices, so their columns are already orthonormal. Nothing needs to be cleaned up afterwards.
- **Perpendicularity.** The row-space basis and the null-space basis are different columns of the same orthogonal V, so RS ⟂ NS is built in. The same goes for CS ⟂ LNS in U.
- **The dimension counts.** V has n columns, split into r + (n − r), so dim RS + dim NS = n. U has m columns, split into r + (m − r), so dim CS + dim LNS = m. These are the identities that the Explain section asks about.

### How the code does it

```python
U, s, Vt = np.linalg.svd(A)
```
This computes the *full* SVD, which is NumPy's default (`full_matrices=True`). U is m×m and Vt is n×n. The full version matters: the reduced SVD keeps only the first min(m, n) columns, so the two null-space bases could come out incomplete.

```python
tol = s.max() * max(m, n) * np.finfo(float).eps
r = int(np.sum(s > tol))
```
This sets the tolerance and counts the rank. In floating point, a singular value that should be exactly 0 comes out around 1e-17. Earlier the third singular value printed as `0.` only because the display was rounded. The tolerance is "machine precision × the size of the matrix × its largest singular value". It's the same rule that `np.linalg.matrix_rank` uses. Anything below it counts as zero.

```python
V = Vt.T
"RS":  V[:, :r],   "NS":  V[:, r:],
"CS":  U[:, :r],   "LNS": U[:, r:],
```
`np.linalg.svd` returns $V^\top$, so the code transposes it to get V. The slices then pick out the columns, exactly as in the table.

### Why this matches the picture

A maps the row space one-to-one onto the column space ($v_i \mapsto \sigma_i u_i$), and it maps the null space to 0. That's the left-panel → right-panel story in the figures.
